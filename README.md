## “云应用”这个词，在雨云这里对应什么

搜“雨云云应用frp”的人，想要的通常是“不自己配 frps 也能穿透”这件事。雨云目前给不了这个。

它的产品线里，最接近“云应用”概念的是虚拟主机：自带 WordPress、Typecho、Discuz 等八种建站程序一键部署。但虚拟主机是共享的建站环境，只跑 PHP 站点，跑不了 frps 这种需要自定义监听端口、常驻进程、还要在防火墙上开口子的服务。游戏云带 MCSM 面板一键开服，那是给 Minecraft 用的，也不是 frp 模板。

所以“云应用 + frp”在雨云这边没有现成产品，只有两条路：

## 两条部署路线：官方二进制还是 Docker

**路线一，官方二进制包加 toml 配置。** 从 frp 官方发布页下对应系统和架构的压缩包，解压后写两个配置文件，`./frps -c frps.toml` 启动。只有一两台内网服务要暴露，这条最快，出问题也最好查——日志直接打在终端上。正式使用建议把 frps 配成 systemd 服务，开机自启，进程挂了自动拉起。

**路线二，Docker。** 适合已经在用容器管服务的人。官方镜像 `fatedier/frpc` 需要自己指定版本标签，比如 `v0.61.2` 这种写法。想用中文界面，有现成的汉化镜像 `firfe/frps` 和 `firfe/frpc`，当前制作版本 0.71.0，AMD64 用 `0.71.0`，ARM64 要加后缀写成 `0.71.0-arm64`。

这条有个坑要提前说：**汉化镜像仓库里没有 `latest` 标签**。`docker pull firfe/frpc` 不加标签会直接失败，必须写全 `firfe/frpc:0.71.0`。

**图形界面这件事值得单独提一句。** frp 从 0.68.0 版本开始改了客户端界面，可以直接在图形界面里创建代理，不用再手改配置文件。如果你打算长期维护好几条隧道，又不想每次开编辑器，用 0.68.0 之后的客户端会省事很多；只是想跑通一条，命令行写 toml 反而更直接。

## 服务端 frps：最小可用配置

云服务器上解压 frp 之后，新建 `frps.toml`：

toml
bindPort = 7000
auth.token = "你的自定义密钥"


两行就够跑起来。`bindPort` 是 frpc 连过来的端口，`auth.token` 是两端共享的密钥，客户端填的必须和这里一字不差。

启动：

bash
./frps -c frps.toml


想加可视化管理后台，新版是在 `webServer` 段里配地址、端口、用户名和密码。这里要留神：网上很多教程写的是 `dashboard_port`、`dashboard_user`、`dashboard_pwd`，那是旧版 ini 格式的字段名，直接搬进 toml 里不生效。

## 客户端 frpc：把内网 80 端口映射出去

内网机器上新建 `frpc.toml`，假设要把本机 80 端口的 Web 服务暴露到云服务器的 8080：

toml
serverAddr = "云服务器公网IP"
serverPort = 7000
auth.token = "你的自定义密钥"

[[proxies]]
name = "web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 80
remotePort = 8080


`serverAddr` 填雨云那台机器的公网 IP，`serverPort` 对应服务端的 `bindPort`，`localPort` 是内网服务真实跑的端口，`remotePort` 是你希望外部访问时用的端口。启动 `./frpc -c frpc.toml`，外部访问 `云服务器公网IP:8080` 就会转到内网那台机器的 80 端口。

**旧教程不能照抄，这是最容易踩的一个坑。** 不少流传的雨云 frp 教程用的是 0.48.0 时代的 ini 写法：

ini
[common]
bind_port = 7000
token = your_secure_token


看起来只是格式差别，实际字段名全变了：`bind_port` 在新版是 `bindPort`，`server_addr` 变成 `serverAddr`，代理段从 `[game_service]` 这种 INI 小节变成 `[[proxies]]` 数组。把旧配置直接喂给新版程序，轻则报解析错误，重则起得来但代理不生效。判断标准很简单：配置文件叫 `.ini` 且开头是 `[common]`，那是旧版；叫 `.toml` 且第一行直接是 `bindPort =`，那是新版。装的是哪个版本，就用哪种格式，别混着来。

顺带说下协议：frp 支持 TCP、UDP、HTTP、HTTPS 等，也带 P2P 通信能力。跑 NAS 管理页、SSH、数据库、Minecraft 联机这些都用 `type = "tcp"`；要给 HTTP 服务挂域名，才需要换成 http 类型并配自定义域名。

## 端口放通：两个端口各管什么，漏一个表现完全不同

云服务器上要放通两个端口，它们的职责完全不一样：

- **`bindPort`（示例 7000）**：给 frpc 连进来用的。只对客户端有意义，外部访问者不需要碰它。
- **`remotePort`（示例 8080）**：给外部访问者用的。你想让谁访问，就得让这个端口对公网开放。

漏掉第一个，frpc 启动后日志会报连接失败，客户端根本连不上服务端。漏掉第二个，frpc 日志显示 `start proxy success`，看起来一切正常，但你在外面用浏览器打 `云服务器IP:8080` 就是超时。两种失败长得完全不一样，先看日志再动手，能省一半排查时间。

端口没放通是内网穿透连不通最常见的原因，比 token 写错还常见。

## 怎么确认真的通了：三项验证

1. 云服务器上 frps 进程在跑，日志里没有报错。
2. 内网机器上 frpc 启动后，日志出现成功连接的提示，比如 `start proxy success` 这类字样。
3. 用一台不在内网的设备，访问 `云服务器IP:remotePort`，能看到内网服务真实的内容，不是错误页也不是超时。

三项全过，链路就是通的。任何一项没过，按这个顺序查：**两端 token 是否完全一致 → `bindPort` 和 `remotePort` 是否都在防火墙放通 → frpc 到底有没有连上 frps**。

已经连上但访问不到服务，只剩两种可能：`remotePort` 没放通，或者内网服务压根没在 `localPort` 上跑。先在局域网里用 `127.0.0.1:localPort` 试一下，能打开再回来查端口。

## 安全上必须做的几件事

frp 把内网服务搬到公网，配置松一点等于把家门钥匙挂在门上。

`auth.token` 用足够长的随机串，别用 `123456` 或者域名拼年份。这个 token 是防止别人蹭你中转节点的唯一屏障，泄露了别人就能拿你的服务器做跳板。

只暴露确实需要的那几个端口，用完就删掉对应的 `[[proxies]]` 段。NAS 管理页、路由器后台、数据库这类东西，别裸奔在公网上，至少在前面叠一层访问鉴权，或者走 SSH 隧道再进。

用 Docker 部署的，镜像标签写死具体版本号，别用 `latest`（汉化镜像本来也没有这个标签）。版本升级前先看官方发布说明，配置字段在版本之间改过不止一次。

最后一条不属于技术范围，但值得写下来：这套东西只用来访问你自己拥有的、合法合规的内网服务。服务商对滥用行为有处置权，这是所有云厂商的通行做法。
